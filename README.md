# 복비 계산기 (calc-realty)

법정 상한요율 기준으로 부동산 중개보수(복비)를 바로 계산해주는 공개용 웹 앱입니다.
기존 "애플부동산 정산 시스템"(apple-realty-settlement)과는 **완전히 별도의 프로젝트**입니다.
정산 시스템은 로그인이 필요한 사무소 내부용이고, 이 앱은 로그인 없이 누구나 쓰는 공개 계산기예요.

## 1. 기술 스택

- Next.js 14.2.35 (App Router) + TypeScript + Tailwind CSS
- 별도 DB/로그인 없음 (계산은 전부 브라우저에서 즉시 처리)
- 예외 1건: `app/api/base-rate`(서버리스 라우트) — 전월세 전환율 계산기가 쓰는 한국은행
  기준금리를 실시간으로 대신 조회해주는 얇은 프록시. DB는 아니지만 첫 서버 API/환경변수라
  아래 "2." 참고
- Vercel Hobby 플랜으로 배포 예정

## 2. 로컬에서 실행하기

```bash
npm install
cp .env.local.example .env.local   # ECOS_API_KEY 채워넣기 (아래 참고)
npm run dev        # http://localhost:3000
```

### 환경변수 — `ECOS_API_KEY` (전월세 전환율 계산기용, 선택사항이지만 강력 권장)

전월세 전환율(3.6) 계산기는 한국은행 ECOS Open API로 **기준금리를 실시간 조회**해서 법정 전환율
상한을 자동 계산합니다. 키가 없어도 앱은 정상 작동하지만(마지막으로 확인해둔 값으로 대체), 형이
매번 직접 기준금리를 확인해줄 필요가 없으려면 키를 발급받아 등록하는 걸 권장합니다.

1. https://ecos.bok.or.kr/api/ 접속 → 회원가입(이메일만 있으면 됨) → `OpenAPI` →
   `인증키 신청` → 활용 목적 간단히 기재(예: "개인 프로젝트 부동산 계산기 개발")
2. 가입 즉시~1일 이내 인증키 발급됨 (`마이페이지` → `인증키 관리`에서 확인)
3. 로컬 개발: `.env.local`에 `ECOS_API_KEY=발급받은키` 추가
4. **프로덕션(Vercel)**: Vercel 프로젝트 → Settings → Environment Variables →
   `ECOS_API_KEY` 이름으로 등록 → 재배포. 이걸 안 하면 프로덕션에서도 폴백값(수동 확인값)으로
   동작함(앱이 죽지는 않지만 실시간 갱신이 안 됨).

계산 로직만 빠르게 검증하려면:

```bash
npm run verify:calc
```

이 스크립트는 매매/전세/월세/오피스텔/토지·상가 등 대표 케이스를 계산해 콘솔에 출력합니다.
(참고: `npm run build`로 실제 프로덕션 빌드도 정상적으로 되는 것을 확인했습니다.)

3.2/3.4(부대비용·일할계산·Cap Rate) 로직은 별도로 `npm run verify:calc2`로 검증합니다.

## 3. 계산 로직 근거

`lib/calc.ts`에 모두 있습니다. 공인중개사법 시행규칙 제20조 및 서울특별시 주택중개보수 조례
(2021.12.30 시행, 국토교통부 표준 개정안과 동일)를 기준으로 했습니다.

- **주택 매매·교환**: 5천만원 미만 0.6%(한도 25만원) ~ 15억 이상 0.7%까지 6단계
- **주택 임대차(전세/월세)**: 5천만원 미만 0.5%(한도 20만원) ~ 15억 이상 0.6%까지 6단계
- **오피스텔(전용 85㎡ 이하 + 요건 충족)**: 매매 0.5% / 임대차 0.4%
- **오피스텔(그 외) · 토지·상가 등**: 0.9% (협의 요율, 상한선)
- **월세 환산 거래금액**: 보증금 + (월세×100), 단 합산액이 5천만원 미만이면 보증금 + (월세×70)
- **부가세**: 중개보수는 부가세 별도. 일반과세 10% / 간이과세 4%(업종별 부가가치율 약 40% 가정
  시 근사치, 참고용) / 면세 선택 가능

⚠️ **주의**: 일부 지자체는 조례가 다를 수 있습니다(대부분 동일하지만 100% 보장은 아님). 앱 하단에
"참고용 안내"라는 문구를 넣어뒀고, 실제 거래에서는 최종적으로 개업공인중개사와 협의해서 결정한다는
점을 명시했습니다. 계산기가 법적 자문이 아니라는 걸 분명히 해두는 게 나중에 분쟁 소지를 줄여줍니다.

## 4. Vercel 배포하기

기존 정산 시스템과 같은 방식입니다.

1. GitHub에 새 저장소 생성 (예: `xchanz-tech/calc-realty`, Public 또는 Private 상관없음)
2. 이 폴더 전체를 그 저장소에 push
   ```bash
   git init
   git add .
   git commit -m "초기 커밋: 복비 계산기"
   git branch -M main
   git remote add origin https://github.com/xchanz-tech/calc-realty.git
   git push -u origin main
   ```
3. https://vercel.com 에서 "Add New Project" → 방금 만든 저장소 선택 → Deploy
   (DB/Auth는 없어서 `.env.local` 없이도 배포·동작은 됩니다. 다만 전월세 전환율 계산기의
   기준금리 실시간 갱신을 쓰려면 위 "2."의 `ECOS_API_KEY`를 Vercel 환경변수에 등록하세요)
4. 배포되면 `calc-realty.vercel.app` 같은 주소가 생깁니다. 커스텀 도메인을 쓰고 싶으면 Vercel
   프로젝트 설정 → Domains에서 추가하면 됩니다.

## 5. 앱인토스(토스 미니앱) 입점 절차

토스 개발자센터(https://developers-apps-in-toss.toss.im) 기준으로 확인한 최신 절차입니다.

### 5-1. 진행 순서

1. **서비스 아이디어 승인**: 앱인토스 콘솔에서 앱 이름/설명 정도만 있어도 신청 가능. 승인까지
   약 2~3일 소요.
2. **미니앱으로 전환(SDK 연동)**: 이미 만든 웹앱(Vercel에 올린 이 프로젝트)에 SDK를 얹는 방식으로
   진행합니다. 처음부터 새로 만들 필요 없이 "기존 웹 프로젝트에 SDK 연동하기" 가이드를 따르면 됩니다.
   ```bash
   npm install @apps-in-toss/web-framework
   npx ait init
   ```
   `granite.config.ts`에 appName/앱 이름/색상/아이콘을 콘솔에 등록한 값과 동일하게 맞춰줍니다.
3. **샌드박스 앱에서 테스트** → **토스앱에서 최종 테스트** → **콘솔에서 검토 요청 → 출시**
4. **사업자 등록**: 출시 자체는 사업자 없이도 가능하지만, **광고 수익화·인앱결제·토스 로그인은
   사업자 등록이 있어야만** 켤 수 있습니다. 개인사업자도 가능합니다.
   - 대표자 본인이 직접 등록하면 **사업자 등록증만** 제출하면 돼요(위임장 등 불필요).
   - **사업자 등록증에 적힌 업종과 미니앱 서비스 업종이 같아야** 합니다. 형은 이미 부동산중개업으로
     사업자 등록이 되어 있으니(애플부동산), 이 부분은 유리한 조건이에요. 다만 "부가가치세 면세
     사업자는 앱인토스 사업자 등록이 불가"하다는 점은 참고하세요.
5. **정산 정보 등록**: 워크스페이스 '정보' 탭에서 계좌 정보 입력 → 검토(영업일 기준 2~3일).
   예금주명은 통장 사본과 한 글자도 다르지 않게 입력해야 합니다.
6. **광고 그룹 생성**: 배너/전면형/리워드 광고 중 선택해 광고 그룹을 만들면 그날부터 수익이
   발생합니다(구글 애드몹 정책 기반, 광고 그룹 ID 발급까지 최대 2시간).

### 5-2. 이 앱에 적용되는 핵심 제약사항

- **로그인**: 앱인토스 내에서는 토스 로그인만 허용됩니다(다른 소셜 로그인 불가). 이 계산기는
  애초에 로그인이 필요 없는 서비스라 문제 없습니다.
- **결제**: 실물 결제는 토스페이만, 디지털 상품은 인앱결제만 허용. 이 앱은 결제 기능 자체가
  없으므로 해당 없음.
- **광고**: 앱인토스 자체 광고(전면형·보상형·배너)만 허용되고, 외부 광고 네트워크(구글 애드센스
  등)는 연동 불가합니다. 즉 수익화는 앱인토스 광고 시스템 안에서만 가능해요.
- **외부 링크/앱 설치 유도 금지**: "자세한 건 홈페이지에서" 같은 유도 문구나 외부 앱 설치 유도는
  반려 사유가 됩니다. 계산 기능은 미니앱 안에서 완결되어야 하는데, 이 계산기는 이미 그렇게
  설계되어 있어 문제 없습니다.
- **금융업 등록 제한과의 관계**: 대출·보험·카드·증권 등 "금융 상품" 관련 서비스는 등록이
  불가능하지만, 이 앱은 금융상품 판매/중개가 아니라 **법정 수수료를 계산해 보여주는 단순 유틸리티**이므로
  이 제한에 해당하지 않을 가능성이 높습니다(토스 안에 이미 대출 계산기·취득세 계산기 등 유사한
  성격의 유틸리티가 있는 것도 같은 맥락입니다). 다만 최종 판단은 심사 단계에서 토스 측이 하므로,
  서비스 아이디어 신청 시 "계산 결과만 제공하며 결제·중개·연결 기능은 없다"는 점을 명확히 적어두는
  게 좋습니다.

### 5-3. 수익화 현실적인 기대치

인앱 광고 수익 = 노출 수 × eCPM ÷ 1,000. 즉 트래픽이 어느 정도 쌓여야 의미 있는 수익이 나옵니다.
초기에는 배너 광고 위주로 시작하고, 사용자가 결과를 다 본 뒤 "결과 복사하기"를 누르는 시점 등에
전면형 광고를 자연스럽게 배치하면 좋습니다(단, 서비스 흐름을 막으면 정책 위반이니 주의).

### 12-1. 같은 세션 이어서 — 전월세 전환율(3.6) & 계약갱신 5% 상한 계산기 추가

형이 "MAX 플랜으로 바뀌었으니 토큰 걱정 말고 전월세 전환율 계산기도 법정 전환율 확인해서

  보증금/월세별 자동 산출." 이건 사실 서로 다른 법령 근거를 가진 두 계산기가 합쳐진 기능:

  2. **계약갱신청구권 행사 시 증액 상한**(같은 법 시행령 제8조) — 갱신 시 차임·보증금 증액은
     약정액의 **20분의 1(5%)**을 초과 불가. 기준금리와 무관한 고정 상한이라 법적 리스크 없음.
- **기준금리 재확인**(웹서치, 2026-08-19): 한국은행이 2026-07-16 금통위에서 기준금리를

### 12-2. 같은 세션 이어서 — 기준금리 실시간 API 연동 (하드코딩 → 자동 갱신)

12-1에서 기준금리를 상수로 하드코딩해뒀는데, 형이 "MAX 플랜이니 매번 사람이 확인 안 해도 되게
자동 갱신으로 만들자"고 해서 실시간 연동으로 업그레이드함. 하드코딩/정기 수동확인/실시간 API
3가지 옵션을 제시했고 형이 **실시간 API 연동**을 선택.

- **신규 서버리스 라우트** `app/api/base-rate/route.ts` — 한국은행 ECOS Open API(통계표
  `722Y001`, 항목코드 `0101000` = 한국은행 기준금리, 일별 시계열)를 서버에서 대신 호출.
  `ECOS_API_KEY` 환경변수 필요(README "2." 참고). 6시간 캐시(`revalidate = 21600`)로 ECOS
  호출을 아낌. 키가 없거나 호출이 실패하면 `lib/jeonseConversion.ts`의
  `FALLBACK_BASE_RATE_PERCENT`(2026-07-16 결정, 2.75%)로 조용히 대체하고 `stale: true`를
  내려줌 — 실패해도 계산기가 멈추지 않는 우아한 저하(graceful degradation) 설계.
- **`lib/jeonseConversion.ts` 리팩터**: `CURRENT_BASE_RATE_PERCENT` → `FALLBACK_BASE_RATE_PERCENT`로
  이름을 바꿔 "이건 폴백용일 뿐, 실제로는 API가 실시간 값을 준다"는 의미를 명확히 함.
  `calcConversion()`이 `currentBaseRatePercent`를 인자로 받아 법정 상한 판정에 실시간 값을
  쓰도록 변경.
- **`components/JeonseConversionCalculator.tsx`**: 마운트 시 `/api/base-rate`를 fetch해서
  기준금리를 받아오고, 전환율 슬라이더 기본값을 실시간 법정 상한으로 자동 세팅(사용자가 슬라이더를
  직접 만지면 그 선택을 존중하고 덮어쓰지 않음 — "법정 상한으로" 버튼으로 언제든 복귀 가능).
  화면에 "한국은행 실시간 확인, YYYY-MM-DD 기준" 또는 실패 시 "실시간 확인 실패 — 마지막
  확인값 사용 중"을 안내 문구로 표시해 사용자가 데이터 신선도를 알 수 있게 함.
- **`.env.local.example` 신규 추가** + README "2."에 ECOS 인증키 발급·Vercel 환경변수 등록
  절차 문서화. `ECOS_API_KEY`는 `.gitignore`의 `.env.local` 패턴에 걸리지 않으므로 예시 파일
  자체는 정상 커밋됨(빈 값).
- `npx tsc --noEmit -p tsconfig.json` 클린 통과(exit 0).
- **형이 해야 할 일**: `ECOS_API_KEY`는 형 계정으로 직접 발급받아야 하는 값이라 Claude가 대신
  가입할 수 없음. https://ecos.bok.or.kr/api/ 에서 무료 가입 후 Vercel 프로젝트 환경변수에
  등록해주면 그 이후로는 완전 자동 — 형이 다시 신경 쓸 일 없음. 키 등록 전까지는 폴백값(2.75%,
  2026-07-16 기준)으로 계속 정상 동작함.
